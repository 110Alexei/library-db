# Library DB — учебная клиент-серверная СУБД для библиотечного каталога

Небольшая самописная база данных для учёта книг в библиотеке: серверная часть написана на C++ (отвечает за хранение, индексацию, разбор запросов и сеть), а клиент — на Python.

## Архитектура

Клиент на Python подключается к серверу по TCP (порт 8080) и отправляет
запрос одной строкой. Сервер (`main.cpp`) принимает соединение, читает
строку запроса и передаёт её в `Query.hpp` — там запрос разбирается и
проверяется на соответствие синтаксису. Если запрос корректен, разобранный
запрос передаётся в `Base.hpp` — движок базы, который хранит все записи в
памяти (модель записи описана в `Record.hpp`), поддерживает индексы по
фамилии и классификации и выполняет по ним выборку, удаление или вставку.
После выполнения запроса сервер отправляет клиенту текстовый ответ обратно
по тому же TCP-соединению и сохраняет текущее состояние базы на диск, в
файл `Data.txt`. Сервер однопоточный.

## Структура проекта

```text
.
├── Record.hpp   # модель записи (книга) + парсинг/сериализация строки файла
├── Query.hpp    # парсер текстового языка запросов
├── Base.hpp     # движок БД: хранение, индексы по фамилии/классификации, выполнение запросов
├── main.cpp     # TCP-сервер, использует Base
├── Client.py    # консольный клиент
└── Generator.py # генератор данных
```

## Формат хранения

Каждая запись — одна строка файла, поля разделены `; `:

```text
фамилия; имя; отчество; "название"; классификация; язык; "издательство"; тираж
```

Пример:

```text
Толстой; Лев; Николаевич; "Война и мир"; Книги/Проза; Русский; "Наука"; 15000
```

`классификация` — иерархическая, до трёх уровней через `/` (например
`Книги/Проза`). Название и издательство — единственные поля в кавычках
(на случай пробелов внутри значения).

## Язык запросов

Запрос — это одна строка вида `КОМАНДА критерии; end;`. Команда задаётся
с большой буквы, после неё — ровно один пробел. Критерии — это пары
`поле="значение"`, разделённые строго `"; "`. Строка обязательно
заканчивается ровно на `"; end;"` (никаких лишних пробелов или переводов
строк после — `client.py` сам их обрезает).

Доступные имена полей в запросах (всегда с маленькой буквы):
`surname`, `name`, `lastname`, `title`, `classification`, `language`,
`publisher`, `circulation`.

| Команда | Назначение | Пример |
| --- | --- | --- |
| `SELECT` | новая выборка по критериям | `SELECT surname="Толстой"; end;` |
| `RESELECT` | сузить **текущую** выборку (после `SELECT`) | `RESELECT language="Русский"; end;` |
| `REMOVE` | удалить записи по критериям | `REMOVE surname="Пушкин"; end;` |
| `INSERT` | добавить новую запись (нужны **все 8** полей) | см. ниже |
| `PRINT` | вывести `all` (всю базу) или `selected` (последнюю выборку) | `PRINT selected; end;` |

Можно указать несколько критериев в одном запросе — они объединяются по
«И» (`SELECT surname="Толстой"; language="Русский"; end;`).

**Поиск по началу строки.** Для `surname`/`name`/`lastname` можно поставить
`*` в конце значения — найдёт всё, что начинается с этой подстроки:
`SELECT surname="Т*"; end;` найдёт Толстого.

**Поиск по классификации.** Можно указать не все уровни — найдутся все
записи в этой ветке: `SELECT classification="Книги"; end;` найдёт и
`Книги/Проза`, и `Книги/Поэзия`, и `Книги/Драма`.

**INSERT** требует ровно 8 полей, каждое в кавычках, порядок в строке
запроса не важен:

```text
INSERT surname="Булгаков"; name="Михаил"; lastname="Афанасьевич"; title="Мастер и Маргарита"; classification="Книги/Проза"; language="Русский"; publisher="АСТ"; circulation="7000"; end;
```

**PRINT** можно ограничить набором полей (через `;`, имена как в таблице
выше), иначе печатает запись целиком:

```text
PRINT selected; surname; title; end;
PRINT all; end;
```
## Генерация тестовых данных

Для генерации больших объёмов используется скрипт `Generator.py`. 

Скрипт автоматизирует процесс создания синтетического библиотечного каталога:
1. При первом запуске проверяет наличие директории `DataGen` и базовых текстовых словарей со списками имён, фамилий, жанров и издательств. Если файлов нет, скрипт разворачивает встроенные дефолтные наборы данных.
2. Случайным образом комбинирует слова между собой, соблюдая синтаксис хранения СУБД.
3. По умолчанию создаёт готовый файл `Data.txt` на **10 000 записей**, который сервер СУБД автоматически подгрузит при следующем старте.

Запуск генератора:
```bash
python3 Generator.py
```
## Запуск
Нужен компилятор с поддержкой C++17 и Python 3.
Заголовки и `main.cpp` — header-only, отдельная сборка `Base.hpp`/`Query.hpp`/
`Record.hpp` не нужна.

```bash
# Сборка и запуск сервера (Record.hpp/Query.hpp/Base.hpp должны лежать рядом с main.cpp)
g++ -std=c++17 -Wall -Wextra main.cpp -o server_app
./server_app
```

В отдельном терминале — клиент:

```bash
python3 client.py
```

## Известные ограничения
* **Один клиент за раз.** Сервер однопоточный; параллельные подключения обрабатываются строго по очереди.
* **Формат хранения.** `"; "` и `"` внутри значений полей (например, в названии книги) сломают разбор строки.
* **Лимит длины запроса** — 1000 байт (`STR_SIZE` в `Query.hpp`). Например, `INSERT` с длинной текстовой классификацией и отчеством может перешагнуть лимит — при подборе значений для классификации стоит иметь это в виду.
* **Один TCP-пакет на запрос/ответ** — клиент и сервер не разбивают длинные сообщения на части.
